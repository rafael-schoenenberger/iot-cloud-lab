# IoT Cloud Lab (iot-cloud-lab)

This repository is a personal project simulating an STM32F4-based IoT asset tracker (GNSS, IMU, environmental sensors, cellular modem) entirely in [Renode](https://renode.io/), running real STM32 HAL-based firmware - no physical hardware required. Everything is orchestrated through Docker.

## Prerequisites

To work with this project effectively, ensure you have the following tools installed:

* **[Docker Desktop](https://www.docker.com/products/docker-desktop/):** For building and running the Renode and firmware-build containers.
* **[VS Code](https://code.visualstudio.com/):** Recommended editor for development.
* **[Git](https://git-scm.com/):** With submodule support, needed to pull in the vendored STM32 HAL/CMSIS libraries.

## Repository Structure

The repository is currently organized logically into the following directories and files: renode, firmware, compose, git specific files, license, readme, and run script
```text

├── .vscode/                # VSCode settings
├── compose/                # Docker Compose orchestration
│   └── docker-compose.yml  # Compose File
├── firmware/               # STM32 HAL-based tracker firmware
│   ├── Dockerfile.sources  # Sources Docker image
│   ├── src/                # main.c, CMakeLists.txt, linker script, HAL config
│   ├── vendor/             # HAL driver, CMSIS device & core (git submodules)
│   └── build/              # Generated by CMake/Ninja, not committed
├── renode/                 # STM32F4 board definition and Renode Docker image
│   ├── Dockerfile.renode   # Renode Docker image
│   ├── boards/             # stm32f4.repl - peripheral/memory map
│   └── scripts/            # stm32f4.resc - boot script, loads firmware.elf
├── .gitignore              # Excludes firmware/build, and local junk
├── .gitmodules             # Vendored HAL/CMSIS submodule definitions
├── LICENSE                 # License Agreement
├── README.md               # This Overview
└── run.ps1                 # Builds firmware, then builds/starts renode

```

## Renode Simulation

The `renode/` directory defines an STM32F407 (Cortex-M4) machine: flash, SRAM, NVIC, RCC, PWR, three UARTs, an I2C bus with simulated ICM-20948/BME280/TMP108 sensors, and GPIO ports - all matched against the real STM32F4 register map. The boot script (`stm32f4.resc`) loads the built `firmware.elf` directly via `sysbus LoadELF`, starts a GDB server on port 3333 for optional interactive debugging, and relays UART3 (debug output) to TCP port 9002.

## Firmware

The `firmware/` directory builds real STM32 HAL-based firmware (`arm-none-eabi-gcc` + CMake/Ninja) against the official ST HAL driver and CMSIS device headers, pulled in as git submodules. It configures UART3 via `HAL_UART_Init`/`HAL_GPIO_Init` and prints a periodic message.

## Docker Orchestration

`compose/docker-compose.yml` runs the firmware build first (a one-shot container that compiles `firmware.elf` and exits), then builds and starts the `renode` service, which loads that firmware at its own startup.

Run `.\run.ps1` any time - initial setup and every later rebuild use the same command. For debug output start e.g. putty and connect to `localhost:9002`, which the UART3 debug output is redirected to, and debug output is shown.
